# 固定学习陪练工作流设计

> 日期：2026-07-13  
> 状态：待用户审阅  
> 适用项目：`self-evolve`

## 背景

Codex App 的每日和每周 cron 自动任务会持续创建独立任务。对需要长期讨论、作业批改和上下文延续的学习场景而言，这会造成任务列表膨胀，并把同一周的学习过程拆散。

本设计取消专门的每日、每周 Codex 自动任务，改用仓库文档保存规则和状态，并由一个固定的“学习陪练”任务承载日常互动。时间提醒由手机、Windows 时钟或日历负责。

## 目标

- 每天形成“学习、输出、批改、讨论、安排下一步”的闭环。
- 每周形成一次基于真实记录的复盘和下周计划。
- 保持一个固定 Codex 任务，避免每天产生新任务。
- 将工作流和进度保存在仓库中，不依赖单个对话的长期上下文。
- 未经用户确认，不把推测内容写入个人记录。

## 文档结构

### `.ai/LEARNING-WORKFLOW.md`

保存完整学习工作流，包括：

- 每日学习闭环。
- 作业和讨论规则。
- 批改标准。
- 每周复盘流程。
- 状态写入和确认边界。
- 中断、超时和未执行时的处理方式。

### `.ai/CONTEXT.md`

只增加稳定的全局规则和入口：

- 固定“学习陪练”任务是日常学习入口。
- 用户触发“开始今日学习闭环”或“开始本周复盘”时，AI 必须先读取 `.ai/LEARNING-WORKFLOW.md`。
- 当前周复盘文件是跨任务恢复学习状态的事实来源。

### `.ai/SESSION-LOG.md`

新增本次会话记录，说明：

- 已决定不使用每日、每周 Codex cron 自动任务承载学习互动。
- 已确定固定任务和文档化工作流。
- 记录每日和每周时间、写入确认规则及下一步。

### `AGENTS.md`

增加简短路由规则，不复制完整流程：

- 遇到学习陪练、作业批改、开放讨论或周复盘请求时，读取 `.ai/LEARNING-WORKFLOW.md`。

## 每日学习闭环

### 学习时段

- 周一至周六，用户在 22:30 前完成当天主要学习。
- 每天投入 60-90 分钟，阅读和作业都包含在该时间内。
- 不强制固定阅读与作业比例，根据内容和难度调整。
- 大型实验课单独规划，不计入日常 60-90 分钟。

### 22:30-23:00 互动

用户在固定“学习陪练”任务中触发“开始今日学习闭环”，或直接提交当天成果。

AI 依次处理：

1. 读取当前周复盘、活跃项目、读书清单和相关作业。
2. 收集当天实际投入、学习内容、理解或答案、卡点。
3. 根据内容选择最合适的输出验证方式。
4. 批改作业或检查理解，随后进行开放讨论。
5. 在 23:00 前收束，生成下一天 60-90 分钟任务。
6. 生成简短的今日学习记录，用户确认后写入当前周复盘。

### 输出形式

不强制每天布置传统作业：

- 编码、计算或可操作内容：小作业。
- 概念理解：用自己的话复述。
- 理财和认知内容：现实案例分析。
- 有多种解释的内容：开放讨论题。
- 掌握不足的内容：针对性补充练习。

### 批改标准

反馈至少覆盖适用的四个维度：

- 正确性。
- 理解深度。
- 应用能力。
- 表达清晰度。

反馈必须指出具体证据、错误和改进方向，不使用空泛评价。

## 每周复盘

### 时间

- 每周日 20:30 开始。
- 建议控制在 30-45 分钟。
- 周日不再执行每日 22:30 闭环。

### 流程

1. 读取当前周每日学习记录、P001、读书清单和本周 Git 变化。
2. 对缺失信息先询问用户，不根据文件变化推测真实完成情况。
3. 复盘技术、理财、认知、职业资产、资产记录、健康执行。
4. 将学习结果区分为“已掌握”“接触过”“未执行”。
5. 汇总完成情况、关键收获、主要阻塞和未解决问题。
6. 保留 `2121` 节奏，只确定下周最重要的 1-3 件事。
7. 大型实验单独列入候选，不自动塞入普通学习时段。
8. 生成本周复盘和下一周计划草稿。
9. 用户确认后更新本周文件并创建下一周复盘文件。

P001、读书清单和路线图只有达到明确通关条件时才建议更新，并需要单独确认。

## 状态与写入规则

- Markdown 仓库是事实来源，对话上下文不是长期状态来源。
- 每日记录写入当前周复盘，不创建每日 Journal 文件。
- 用户没有明确提供的信息保持空白，不由 AI 补全。
- 所有个人完成情况、评分、资产和健康数据必须经用户确认。
- 不自动执行 Git commit 或 Trilium 同步。
- 不自动修改长期方向、路线顺序或任务量。

## 中断与异常处理

- 当天未学习：如实记录原因，只安排下一次最低恢复任务。
- 未在 22:30 提交：之后仍可继续当天流程，不生成虚假记录。
- 作业错误较多：下一次优先纠错，减少新内容。
- 讨论超过 23:00：记录未解决问题，后续继续。
- 学习中断：不补历史欠账，从当前节奏恢复。
- 固定任务不可用：在项目下创建新任务并使用相同触发语，AI 从仓库恢复状态。

## Codex 任务管理

- 长期保留一个名为“学习陪练”的固定任务。
- 日常学习、作业提交、批改和讨论在该任务中进行。
- 周复盘也在同一任务中完成。
- 不创建每日或每周 Codex cron 自动任务。
- 提醒由外部日历、手机或 Windows 时钟负责。

## 验收标准

- 触发每日学习闭环时，AI 能按规定收集信息、批改、讨论和安排下一步。
- 触发周复盘时，AI 能从当前周文件恢复状态并生成可靠草稿。
- 未经确认不会修改个人记录。
- 新任务能够通过读取仓库恢复相同工作流。
- Codex App 不会因每日执行持续产生新的自动任务。
