# Weekly Journal Reset 设计

## 背景

用户要求从本周 `2026-W30` 开始重置 `4-Journal/weekly/`，只保留新的周模板和本周周复盘文件，其余历史周文件与示例文件删除。

现有周模板主要面向“周末一次性复盘”，但当前学习工作流要求：

- 每日记录直接写入当前周复盘；
- 周日复盘要区分“已掌握 / 接触过 / 未执行”；
- 周复盘只保留事实，不伪造完成情况。

## 目标

- 重写 `4-Journal/weekly/_template.md`，使其匹配当前学习陪练工作流。
- 创建 `4-Journal/weekly/2026-W30.md` 作为本周起点文件。
- 删除 `4-Journal/weekly/2026-W28.md`、`4-Journal/weekly/2026-W29.md`、`4-Journal/weekly/example-weekly-review.md`。

## 设计

### 模板结构

模板分为四块：

1. 本周信息：时间范围、本周类型、活跃项目、本周目标。
2. 2121 节奏：保留固定周安排，方便每周复用。
3. 每日记录：周一到周六按“项目 / 投入 / 内容 / 产出 / 卡点”记录事实。
4. 周日复盘：按 P001、P002、P003 分别记录“已掌握 / 接触过 / 未执行 / 下周最小任务”，再补职业资产、资产记录、健康执行与下周 1-3 件事。

### 本周文件

`2026-W30.md` 直接基于新模板创建，但只预填本周真实日期和当前活跃项目，不填任何完成情况。

## 非目标

- 不回写或迁移旧周数据。
- 不修改月复盘、年复盘或学习工作流文件。
- 不自动提交 Git。

## 验证

- `4-Journal/weekly/` 最终只保留 `_template.md` 和 `2026-W30.md`。
- 新模板包含“每日记录”和“已掌握 / 接触过 / 未执行”结构。
- `git diff --check` 通过。
