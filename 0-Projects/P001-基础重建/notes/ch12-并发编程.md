# 第 12 章 — 并发编程

## 本章概逊

本章教你如何编写同时处理多个任务的程序。从基于进程的并发、基于 I/O 多路复用的并发，到基于线程的并发，最后讨论并行编程。这是 CSAPP 最后也是实用性最强的一章——你日常写的 Flutter/Dart 代码几乎每时每刻都在和并发打交道。

## 核心概念

### 概念 1：并发 vs 并行
- 一句话定义：并发是同时处理多个任务（交替执行），并行是同时执行多个任务（多核同时）。
- 为什么重要：混淆两者会导致错误的性能预期。单核 CPU 可以并发但不能并行。
- 关键区别：
  - 并发：关注任务的结构（如何组织多个任务）
  - 并行：关注执行的效率（如何利用多核加速）

### 概念 2：基于进程的并发
- 一句话定义：每个客户端连接 fork 一个子进程处理。
- 优点：进程间地址空间隔离，一个崩溃不影响其他
- 缺点：进程创建开销大，进程间通信复杂（需要 IPC：管道、共享内存、信号）
- 关键问题：需要回收僵尸进程（SIGCHLD 信号处理）、避免文件描述符泄漏

### 概念 3：基于 I/O 多路复用的并发
- 一句话定义：用一个进程通过 select/poll/epoll 同时监控多个文件描述符，哪个有数据就处理哪个。
- 优点：单进程，无需同步，开销小
- 缺点：编程复杂（状态机模型），不能利用多核
- 关键函数：select() — 传入一组 fd，阻塞直到至少一个 fd 可读/可写
- 适用场景：高并发、短连接的网络服务器（如 Nginx）

### 概念 4：基于线程的并发
- 一句话定义：多个线程在同一进程内并发执行，共享地址空间。
- 优点：比进程轻量，共享内存方便
- 缺点：共享状态需要同步，容易出现竞态条件
- 关键区别：
  - 线程共享：代码段、数据段、堆、文件描述符
  - 线程私有：栈、寄存器、程序计数器

### 概念 5：同步机制
- 一句话定义：保护共享资源不被多个线程同时修改。
- 关键原语：
  - 互斥锁（Mutex）：lock/unlock，同一时刻只有一个线程能持有
  - 信号量（Semaphore）：P（wait）和 V（signal），允许 N 个线程同时进入
  - 条件变量（Condition Variable）：wait/signal，用于"等待某个条件成立"
- 经典问题：
  - 生产者-消费者问题：缓冲区满时生产者等待，缓冲区空时消费者等待
  - 读者-写者问题：多个读者可以同时读，但写者需要独占

### 概念 6：线程安全
- 一句话定义：函数在多线程环境下被调用时能产生正确结果。
- 四类线程不安全函数：
  1. 不保护共享变量（如 static 变量）→ 加锁解决
  2. 跨调用保持状态（如 strtok）→ 用传参版本（strtok_r）
  3. 返回指向静态变量的指针 → 调用者复制
  4. 调用其他线程不安全函数 → 递归问题
- 可重入函数：不依赖任何共享状态，天然线程安全。

### 概念 7：并行编程
- 一句话定义：利用多核加速计算密集型任务。
- 关键策略：
  - 分治（Divide and Conquer）：将大问题分成子问题，各核处理一部分
  - 关键挑战：负载均衡（如何让每个核的工作量大致相等）和通信开销

## 难点预警

- 竞态条件（Race Condition）的 bug 难以复现和调试——需要用工具（如 ThreadSanitizer）辅助
- 生产者-消费者问题的同步代码需要反复推敲，一个锁的顺序错误就可能导致死锁
- 理解并发最好的方式是写代码 + 遇到 bug + 修 bug

## 与 Flutter/Dart 的关联

**这是和 Flutter/Dart 关联最紧密的一章。**

- **async/await**：Dart 的 async/await 本质上是"基于事件循环的并发"（单线程 + I/O 多路复用的变体）。`Future` 就是一个"将来才有值"的占位符，事件循环负责调度。
- **Isolate = 进程模型**：Dart 的 Isolate 更接近"基于进程的并发"——独立的内存空间，通过消息通信（SendPort/ReceivePort）。
- **compute() 函数**：Flutter 的 `compute()` 是创建 Isolate 的便捷方法，用于将 CPU 密集型任务放到后台 Isolate（并行），不阻塞 UI 线程。
- **Stream**：Dart 的 `Stream` 是异步数据流，类似于事件循环中的消息队列。`StreamController` 类似于生产者-消费者模型中的缓冲区。
- **Completer**：Dart 的 `Completer` 类似于条件变量——你等待一个条件（异步操作完成），完成后通知等待者。
- **为什么 Flutter 是单线程的**：UI 渲染必须是串行的（否则界面会乱），所以 Flutter 用单线程事件循环处理 UI 事件，用 Isolate 处理 CPU 密集型任务。这和"I/O 多路复用 + 线程池"的混合模式是一致的。

## 关键术语对照

| 英文 | 中文 | 一句话解释 |
|------|------|-----------|
| concurrency | 并发 | 同时处理多个任务 |
| parallelism | 并行 | 同时执行多个任务 |
| thread | 线程 | 进程内的执行单元 |
| mutex | 互斥锁 | 保证同一时刻只有一个线程进入 |
| semaphore | 信号量 | 允许 N 个线程同时进入 |
| race condition | 竞态条件 | 多线程访问共享资源的错误 |
| deadlock | 死锁 | 互相等待对方释放资源 |
| reentrant | 可重入 | 不依赖共享状态的函数 |
| thread-safe | 线程安全 | 多线程环境下结果正确 |
| event loop | 事件循环 | 单线程异步调度的核心机制 |
