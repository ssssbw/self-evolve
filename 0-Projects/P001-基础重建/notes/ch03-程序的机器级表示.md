# 第 3 章 — 程序的机器级表示

## 本章概览

本章教你读懂 x86-64 汇编语言。你不需要用汇编写程序，但能读懂它意味着你可以调试编译器的输出、理解性能瓶颈、分析安全漏洞。这是 CSAPP 中最难也最有价值的一章。

## 核心概念

### 概念 1：x86-64 寄存器
- 一句话定义：CPU 内部的高速存储单元，x86-64 有 16 个 64 位通用寄存器。
- 为什么重要：所有运算都在寄存器之间进行，理解寄存器是读懂汇编的前提。
- 关键寄存器：
  - %rax：返回值
  - %rsp：栈指针（指向栈顶）
  - %rbp：帧指针（指向当前栈帧底部）
  - %rdi, %rsi, %rdx, %rcx, %r8, %r9：函数参数（前 6 个）
  - %rbx, %r12-%r15：被调用者保存的寄存器
- 关键特性：每个 64 位寄存器可按 32/16/8 位访问（%eax 是 %rax 的低 32 位）

### 概念 2：操作数格式
- 一句话定义：汇编指令操作的数据来源，分为立即数、寄存器和内存引用。
- 关键格式：
  - 立即数：$0x1F（前面加 $）
  - 寄存器：%rax
  - 内存引用：D(Rb, Ri, S) = Mem[Rb + R_i × S + D]（最复杂的格式）

### 概念 3：数据移动指令（mov）
- 一句话定义：在寄存器和内存之间复制数据。
- 为什么重要：这是最常见的指令，没有之一。
- 关键规则：
  - mov S, D：S → D
  - 不能两个操作数都是内存（需要两条指令）
  - movz/movs：零扩展/符号扩展移动

### 概念 4：栈帧与函数调用
- 一句话定义：每次函数调用在栈上分配一块空间（栈帧），存参数、局部变量和返回地址。
- 为什么重要：理解栈帧是理解函数调用、递归、调试信息的关键。
- 关键过程：
  1. 调用前：caller 把参数放入寄存器/栈
  2. call 指令：把返回地址压栈，跳转到被调函数
  3. 被调函数：push %rbp 保存旧帧指针，设置新帧指针
  4. 函数体执行
  5. leave 指令：恢复栈指针和帧指针
  6. ret 指令：弹出返回地址，跳回调用者

### 概念 5：控制流（条件码与跳转）
- 一句话定义：CPU 通过条件码寄存器记录最近一次运算的状态（进位、零、负、溢出），用于条件分支。
- 关键条件码：CF（进位）、ZF（零）、SF（负）、OF（溢出）
- 关键指令：
  - cmp S1, S2：计算 S2 - S1 设置条件码
  - test S1, S2：计算 S1 & S2 设置条件码
  - je/jne/jl/jg/...：根据条件码跳转
- 条件移动（cmov）：不跳转，而是条件性地移动数据。现代 CPU 更喜欢 cmov，因为不会破坏流水线。

### 概念 6：过程调用中的寄存器使用约定
- 一句话定义：调用者和被调用者对寄存器保存的责任划分。
- 关键规则：
  - 调用者保存（caller-saved）：%rax, %rcx, %rdx, %rsi, %rdi, %r8-%r11 —— 调用函数前，如果你需要保留这些值，自己压栈
  - 被调用者保存（callee-saved）：%rbx, %rbp, %r12-%r15 —— 被调函数保证这些寄存器在返回时值不变

## 难点预警

**这是全书最难的章节。** 具体难点：
- 汇编语法不直观，尤其是 AT&T 语法（源在前，目的在后，和 Intel 语法相反）
- 栈帧的变化过程需要动态想象，建议用纸笔画图
- Bomb Lab 会让你非常痛苦，但也非常有成就感

**攻克建议：**
- 每读一个代码示例，都手动在纸上跟踪寄存器和栈的变化
- 先搞懂 mov、push/pop、call/ret 这四个最基础的指令
- 不理解的地方用 `gcc -S` 或 `objdump -d` 看真实编译输出

## 必做练习

- **Bomb Lab**（CSAPP 经典实验）—— 拆解"炸弹"（6 个阶段），每阶段需要读懂汇编找到正确输入
- 用 `gcc -O1 -S` 编译一个简单 C 函数，逐行注释汇编
- 手动跟踪一个递归函数（如阶乘）的栈帧变化

## 与 Flutter/Dart 的关联

- **函数调用约定**：Dart FFI（Foreign Function Interface）让你直接调用 C 函数。理解参数传递（前 6 个走寄存器）和栈帧，才能正确使用 FFI。
- **调试能力**：当 Flutter app crash 在 native 层（如第三方 SDK），你看到的 stack trace 就是汇编 + 内存地址。能读懂汇编就能定位问题。
- **条件分支与性能**：Flutter 渲染管线中大量使用条件判断。理解分支预测和 cmov 的概念，有助于理解为什么 Flutter 在列表滚动时强调"避免在 build 方法中做重计算"。

## 关键术语对照

| 英文 | 中文 | 一句话解释 |
|------|------|-----------|
| register | 寄存器 | CPU 内部的高速存储 |
| operand | 操作数 | 指令操作的数据 |
| stack frame | 栈帧 | 一个函数在栈上的空间 |
| instruction pointer | 指令指针 | %rip，指向下一条要执行的指令 |
| calling convention | 调用约定 | 函数调用时参数传递和寄存器使用的规则 |
| callee-saved | 被调用者保存 | 被调函数负责保持不变的寄存器 |
| caller-saved | 调用者保存 | 调用者自行保存的寄存器 |
| condition code | 条件码 | CPU 记录运算状态的标志位 |
| branch prediction | 分支预测 | CPU 猜测条件跳转的方向 |
| calling convention | 调用约定 | 参数传递和返回值的规则 |
