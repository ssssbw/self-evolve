# 第 1 章 — 计算机系统漫游

## 本章概览

CSAPP 的开篇地图。不深入任何主题，而是从全局视角展示一个 C 程序从源代码到运行结果的全过程。读完这章，你应该对"计算机系统"有一个完整的鸟瞰图。

## 核心概念

### 概念 1：信息就是位 + 上下文
- 一句话定义：所有数据（源代码、数字、图片）在计算机中都是一串 0 和 1，区别在于如何解读（上下文）。
- 为什么重要：这是整个 CS 的基础假设。同一段二进制，在不同的上下文下可以表示整数、浮点数、指令或字符串。
- 关键图示：一个 hello.c 文件本质上是一串字节序列，每 8 位一个字节，ASCII 编码映射到字符。

### 概念 2：程序从源代码到运行的完整链路
- 一句话定义：源文件 → 预处理器 → 编译器 → 汇编器 → 链接器 → 可执行文件 → 加载器 → 进程。
- 为什么重要：理解这条链路，才能定位"编译错误""链接错误""运行时错误"分别发生在哪个环节。
- 关键过程：
  1. 预处理（cpp）：处理 #include、#define，生成 .i 文件
  2. 编译（ccl）：将 .i 翻译为汇编，生成 .s 文件
  3. 汇编（as）：将汇编翻译为机器码，生成 .o 文件
  4. 链接（ld）：合并多个 .o 和库，生成可执行文件

### 概念 3：存储器层次结构
- 一句话定义：计算机的存储设备按速度和容量分层排列，从快到慢：寄存器 → L1 缓存 → L2 缓存 → L3 缓存 → 主存 → 磁盘 → 网络。
- 为什么重要：理解这个层次是写出高性能代码的基础。你的代码慢，往往是因为没有利用好缓存。
- 关键原则：越快越小越贵，越慢越大越便宜。每层之间用缓存机制传递数据。

### 概念 4：操作系统抽象
- 一句话定义：OS 通过三个抽象概念管理硬件：进程（对 CPU 的抽象）、虚拟内存（对内存的抽象）、文件（对 I/O 设备的抽象）。
- 为什么重要：你写的所有代码都运行在这三个抽象之上。理解它们，就理解了"你的程序到底在什么环境里跑"。

### 概念 5：并发与并行
- 一句话定义：并发是同时处理多个任务（切换执行），并行是同时执行多个任务（多核）。
- 为什么重要：现代程序几乎都是并发的。Flutter 的 async/await、Dart 的 isolate、Go 的 goroutine 都在处理这个问题。

## 与 Flutter/Dart 的关联

- **编译链路**：Dart 代码在开发模式下是 JIT 编译（类似解释执行），在 release 模式下是 AOT 编译为机器码（类似传统编译）。Flutter build 过程本质上和 C 的编译链路一样：dart 源码 → kernel（类似汇编）→ machine code。
- **存储器层次**：Flutter 的图片缓存（ImageCache）就是一个典型的缓存层。LRU 策略决定了哪些图片留在内存（快），哪些被清理后需要重新从网络加载（慢）。
- **进程抽象**：Dart 的 isolate 本质上是一个轻量级进程，有自己的内存空间，不共享状态。

## 关键术语对照

| 英文 | 中文 | 一句话解释 |
|------|------|-----------|
| bit | 位 | 最小的数据单位，0 或 1 |
| byte | 字节 | 8 位组成一个字节 |
| source file | 源文件 | 程序员编写的文本文件 |
| preprocessor | 预处理器 | 处理 #include、#define 等指令 |
| compiler | 编译器 | 将高级语言翻译为汇编 |
| assembler | 汇编器 | 将汇编翻译为机器码 |
| linker | 链接器 | 合并多个目标文件和库 |
| executable | 可执行文件 | 可以被加载运行的二进制文件 |
| process | 进程 | 运行中的程序实例 |
| virtual memory | 虚拟内存 | 每个进程看到的独立内存空间 |
| context switch | 上下文切换 | CPU 从一个进程切换到另一个 |
| cache | 缓存 | 小而快的存储，用于加速访问慢存储 |
| concurrency | 并发 | 同时处理多个任务 |
| parallelism | 并行 | 同时执行多个任务 |
