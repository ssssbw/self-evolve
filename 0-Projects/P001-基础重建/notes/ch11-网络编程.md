# 第 11 章 — 网络编程

## 本章概览

讲解如何用 socket API 编写网络程序。从客户端-服务器模型入手，涵盖 TCP 连接的建立、数据传输和关闭。本章是理解 HTTP、WebSocket 等协议的基础，也是走向后端开发的必经之路。

## 核心概念

### 概念 1：客户端-服务器模型
- 一句话定义：客户端发起请求，服务器响应请求，通过网络通信。
- 为什么重要：几乎所有网络应用（Web、App、游戏）都基于这个模型。
- 关键特点：
  - 服务器是被动方（监听等待连接）
  - 客户端是主动方（发起连接）
  - 一个服务器可以同时服务多个客户端

### 概念 2：Socket 接口
- 一句话定义：操作系统提供的网络编程 API，socket 是网络连接的端点。
- 关键函数：
  - socket()：创建一个 socket fd
  - connect()：客户端连接服务器
  - bind()：服务器绑定地址和端口
  - listen()：服务器开始监听
  - accept()：服务器接受一个新连接（返回新的 fd）
  - read()/write()：在 socket 上收发数据
  - close()：关闭连接

### 概念 3：TCP 连接的生命周期
- 一句话定义：TCP 连接的三次握手建立、数据传输、四次挥手关闭。
- 关键过程：
  1. 三次握手：客户端 SYN → 服务器 SYN-ACK → 客户端 ACK
  2. 数据传输：双工，双方都可以发数据
  3. 四次挥手：主动关闭方 FIN → 被动方 ACK → 被动方 FIN → 主动方 ACK
- 关键状态：TIME_WAIT（主动关闭方等待 2MSL 后才真正关闭）

### 概念 4：网络字节序
- 一句话定义：网络协议使用大端序（Big-Endian），但主机可能是小端序（x86-64）。
- 关键函数：htonl/htons（主机→网络）、ntohl/ntohs（网络→主机）
- 为什么要转换：不同架构的主机字节序不同，网络传输需要统一。

### 概念 5：并发服务器
- 一句话定义：一个服务器进程同时处理多个客户端连接。
- 关键实现方式：
  - 每个连接 fork 一个子进程（简单但开销大）
  - 使用 I/O 多路复用（select/poll/epoll）——单进程处理多连接
  - 使用线程（比进程轻量）

## 难点预警

- Socket API 函数较多，需要结合代码理解调用顺序
- 并发服务器的实现需要结合第 8 章和第 12 章的知识
- 网络字节序的概念简单但容易忘记转换

- 写一个 echo 客户端和服务器（客户端发什么，服务器回什么）

## 与 Flutter/Dart 的关联

- **Dart 的 HttpClient**：`dart:io` 中的 `HttpClient` 封装了 socket 操作。每次 `http.get('https://...')` 底层就是：socket() → connect() → write(HTTP请求) → read(HTTP响应) → close()。
- **Flutter 的网络层**：`http` 包、`dio` 包都是 socket 的高级封装。理解 socket 原理有助于排查网络超时、连接失败等问题。
- **WebSocket**：Flutter 的 `WebSocket.connect()` 底层是先建立 TCP 连接，然后升级为 WebSocket 协议。理解 TCP 连接过程有助于理解 WebSocket 的生命周期。
- **gRPC**：你在技术路线图中会学到 gRPC，它基于 HTTP/2，而 HTTP/2 基于 TCP。理解 socket 是理解整个网络栈的基础。
- **WebSocket 和热重载**：`flutter run` 的热重载通过 WebSocket 连接实现——开发工具是 WebSocket 客户端，设备上的 Dart VM 是 WebSocket 服务器。

## 关键术语对照

| 英文 | 中文 | 一句话解释 |
|------|------|-----------|
| socket | 套接字 | 网络连接的端点 |
| TCP | 传输控制协议 | 可靠的、面向连接的传输协议 |
| UDP | 用户数据报协议 | 不可靠的、无连接的传输协议 |
| port | 端口 | 进程级别的网络地址 |
| byte order | 字节序 | 多字节数据的存储顺序 |
| big-endian | 大端序 | 高位字节在低地址 |
| little-endian | 小端序 | 低位字节在低地址 |
| three-way handshake | 三次握手 | TCP 建立连接的过程 |
| four-way teardown | 四次挥手 | TCP 关闭连接的过程 |
| I/O multiplexing | I/O 多路复用 | 单进程管理多个 I/O 通道 |
