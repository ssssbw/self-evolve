# 第 6 章 — 存储器层次结构

## 本章概览

本章详细讲解计算机的存储体系——从 CPU 寄存器到磁盘，每一层都是下一层的缓存。理解缓存的工作原理，是写出高性能代码的关键。本章是 CSAPP 中实用性最强的章节之一。

## 核心概念

### 概念 1：局部性原理（Locality）
- 一句话定义：程序倾向于重复使用最近用过的数据（时间局部性）和附近的数据（空间局部性）。
- 为什么重要：局部性是整个存储层次结构有效运转的基础——没有局部性，缓存就没有用。
- 关键判断：
  - 时间局部性好：循环中反复读同一个变量
  - 空间局部性好：顺序遍历数组（stride-1 访问）
  - 局部性差：随机跳跃访问链表节点

### 概念 2：缓存基本原理
- 一句话定义：缓存是一个小而快的存储层，保存大数据中"最近最可能用到"的子集。
- 关键指标：
  - 命中（Hit）：要找的数据在缓存里
  - 缺失（Miss）：要找的数据不在缓存里，需要从下一层取
  - 命中率（Hit Rate）：命中次数 / 总访问次数
  - 命中时间（Hit Time）：访问缓存的时间（通常 1-10 个周期）
  - 缺失惩罚（Miss Penalty）：从下一层取数据的时间（可能 100+ 个周期）

### 概念 3：缓存映射方式
- 一句话定义：决定一个内存块可以放在缓存的哪个位置。
- 三种方式：
  - 直接映射（Direct-Mapped）：每个内存块只能映射到缓存的一个固定位置（E=1）
    - 优点：简单快速
    - 缺点：冲突缺失——不同内存块映射到同一位置会互相驱逐
  - 组相联（Set-Associative）：每个内存块可以放在一组中的任意位置（E > 1）
    - 平衡了速度和灵活性
  - 全相联（Fully Associative）：内存块可以放在缓存任意位置（E=C)
    - 优点：冲突缺失最少
    - 缺点：搜索代价高，只适合小缓存（如 TLB）

### 概念 4：缓存缺失的分类（3C）
- 一句话定义：所有缺失分三类，不同类型有不同的解决方案。
- 关键分类：
  - 冷缺失（Cold / Compulsory Miss）：第一次访问某个块，缓存里当然没有——无法避免
  - 冲突缺失（Conflict Miss）：不同的块映射到同一组，互相驱逐——增加关联度可缓解
  - 容量缺失（Capacity Miss）：缓存太小，放不下所有需要的数据——增大缓存可缓解

### 概念 5：写策略
- 一句话定义：缓存数据被修改后，如何同步到下一层。
- 关键策略：
  - 写直达（Write-Through）：每次写都同时写缓存和下一层——简单但慢
  - 写回（Write-Back）：只写缓存，被驱逐时才写回下一层——快但复杂
  - 写分配（Write-Allocate）：缺失时先把块加载到缓存再写——利用空间局部性
  - 非写分配（No-Write-Allocate）：缺失时直接写下一层——不浪费缓存空间

### 概念 6：缓存对程序性能的影响
- 一句话定义：你的代码慢，很可能是缓存命中率低。
- 关键规律：
  - **数组 vs 链表**：数组有好的空间局部性，链表没有
  - **行优先 vs 列优先遍历**：C 语言数组按行存储，行优先遍历空间局部性远好于列优先
  - **工作集大小**：如果活跃数据 > 缓存大小，会出现大量容量缺失
  - **分块（Blocking/Tiling）**：把大问题分成小块，让每块适配缓存

## 难点预警

- 缓存映射的地址计算（组索引、块偏移、标记位）需要动手算几遍才能建立直觉
- 分块矩阵乘法的例子很精彩但需要耐心推导——这是面试经典题

## 与 Flutter/Dart 的关联

- **ImageCache**：Flutter 的图片缓存就是一个经典的 LRU 缓存。`imageCache.maximumSize` 控制缓存容量，超过容量就会驱逐最近最少使用的图片——和 CPU 缓存的替换策略一样。
- **ListView 性能**：为什么 ListView.builder 比 Column + List.generate 快？因为 builder 只渲染可见区域的 Widget（工作集小），而 generate 一次性创建所有 Widget（工作集大，超出"缓存"）。
- **Dart 的 List vs LinkedList**：List（内部是数组）的遍历速度远快于 LinkedList，因为连续内存布局有更好的空间局部性。
- **数据库查询优化**：SQLite（Flutter 常用）的 B-tree 页面缓存，本质上和 CPU 缓存是同一个原理。

## 关键术语对照

| 英文 | 中文 | 一句话解释 |
|------|------|-----------|
| locality | 局部性 | 程序倾向于重复使用近期和附近的数据 |
| temporal locality | 时间局部性 | 最近用过的数据很可能再用 |
| spatial locality | 空间局部性 | 用过数据附近的数据很可能被用到 |
| cache line / block | 缓存行/块 | 缓存和内存之间传输的最小单位 |
| hit | 命中 | 在缓存中找到了需要的数据 |
| miss | 缺失 | 在缓存中没找到 |
| eviction | 驱逐 | 从缓存中移除一个块腾出空间 |
| tag | 标记 | 判断缓存块是否是所需数据的标识 |
| set | 组 | 缓存中可以放置同一组块的位置集合 |
| associativity | 关联度 | 每组中可以放置的块数 |
| LRU | 最近最少使用 | 常见的缓存替换策略 |
| blocking / tiling | 分块 | 将大问题分成适配缓存的小块 |
