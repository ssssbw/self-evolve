# 第 5 章 — 优化程序性能

## 本章概览

教你怎么写出跑得更快的代码。核心思想：先写正确的代码，再通过系统化的方法找到瓶颈，针对性优化。不是教你"猜哪里慢"，而是教你"怎么证明哪里慢"。

## 核心概念

### 概念 1：性能度量方法
- 一句话定义：用 CPE（Cycles Per Element，每个元素需要的时钟周期数）衡量程序性能。
- 为什么重要：有了量化指标，才能判断优化是否有效，而不是靠直觉。
- 关键工具：用 clock() 或 gettimeofday() 测量时间，用 gprof 或 perf 找热点函数。

### 概念 2：消除低效循环
- 一句话定义：把循环内不变的 computation 移到循环外（代码移动 / Code Motion）。
- 为什么重要：这是最简单、最有效的优化之一。一个在循环里调用了 N 次但实际上每次结果一样的函数，只需要调用 1 次。
- 经典例子：`for (i = 0; i < strlen(s); i++)` —— strlen 每次循环都重新扫描整个字符串，O(n^2)。把它移到循环外就是 O(n)。

### 概念 3：减少过程调用
- 一句话定义：函数调用有开销（保存寄存器、参数传递、栈帧管理），在热循环中内联可以消除这些开销。
- 为什么重要：编译器的内联决策不一定最优，有时需要你手动消除不必要的函数边界。

### 概念 4：循环展开（Loop Unrolling）
- 一句话定义：每次循环多处理几个元素，减少循环次数和分支预测开销。
- 为什么重要：减少循环控制开销（条件判断、跳转），增加指令级并行机会。
- 关键形式：k × 1 展开（每次处理 k 个元素，一个累加器）和 k × k 展开（k 个元素分别累加，最后合并）。

### 概念 5：利用指令级并行
- 一句话定义：现代 CPU 可以同时执行多条不相关的指令，通过多个累加变量来暴露这种并行性。
- 为什么重要：这是手动优化的天花板——k × k 展开利用了 CPU 的超标量能力。
- 关键原理：两个独立的加法操作可以在不同的 ALU 上同时执行（如果 CPU 有多个执行单元）。

### 概念 6：性能极限估算
- 一句话定义：根据数据流图的关键路径长度，估算一段循环代码的理论最快速度。
- 关键概念：
  - 延迟界限（Latency Bound）：串行执行时的最慢速度
  - 吞吐量界限（Throughput Bound）：硬件执行单元的极限速度
  - 实际性能在两者之间

## 难点预警

- 理解数据流图需要画出循环中每步的依赖关系，比较抽象
- 不要纠结于具体的周期数——重点是掌握优化方法论

## 必做练习

- 用 `gcc -O1` 和 `gcc -O3` 编译同一个程序，对比性能差异
- 手动将一个简单的循环展开 2×2，观察性能变化

## 与 Flutter/Dart 的关联

- **Flutter 的 build 方法优化**：`const` 构造函数就是"代码移动"的变体——不变的东西不要每次 rebuild。把 `const Widget()` 放到 build 方法外，就是从 O(n) 降为 O(1)。
- **列表性能**：ListView.builder 的懒加载本质上是一种"减少不必要计算"的优化。如果你用 `Column(children: List.generate(10000, ...))` 一次性创建所有子 Widget，就是在做循环内不必要的工作。
- **Dart 编译器优化**：Dart AOT 编译器会做内联、循环展开等优化。理解这些原理有助于你写出编译器友好（更容易被优化）的代码。

## 关键术语对照

| 英文 | 中文 | 一句话解释 |
|------|------|-----------|
| CPE | 每元素周期数 | 衡量循环性能的指标 |
| code motion | 代码移动 | 把不变计算移到循环外 |
| loop unrolling | 循环展开 | 每次循环多处理几个元素 |
| inline | 内联 | 消除函数调用开销 |
| critical path | 关键路径 | 数据流图中最长的依赖链 |
| superscalar | 超标量 | CPU 同时执行多条指令的能力 |
| branch prediction | 分支预测 | CPU 猜测条件跳转方向 |
| profiling | 性能分析 | 找到程序的热点代码 |
