## 项目定位

Self-Evolve AI 助手是 P004 的长期主 Challenge，也是用于验证 AI 全栈能力金字塔的公开作品。

它面向个人长期学习与成长规划，将现有学习陪练工作流产品化：读取当前项目和学习状态、生成学习任务、接收用户提交、提供批改与讨论、等待用户确认学习记录、写入 Markdown，并按需同步到 Trilium。

## 已确认的产品边界

- Markdown/Git 是唯一事实来源。
- App 读取和写入 Markdown，不以 Trilium 或应用数据库替代个人知识库。
- Trilium 是单向同步镜像，不承担双向编辑和冲突合并。
- 用户始终拥有项目状态、完成情况、评分和学习记录的最终确认权。
- AI 不根据 Git 变化或文件存在情况推测用户已经学习或掌握。
- 项目以手写学习为主，AI 只承担解释、提示、追问、调试辅助和 Code Review。

## 完整学习闭环

1. 读取活跃项目、当前周记录、相关 Challenge 和卡点。
2. 根据可用时间和项目优先级生成今日任务。
3. 用户完成学习并提交自己的理解、答案、代码或问题。
4. AI 从正确性、理解深度、应用能力和表达清晰度提供反馈。
5. AI 生成简短学习记录草稿，等待用户确认。
6. 将确认后的记录写入 Markdown 知识库。
7. 用户明确触发后，将 Markdown 单向同步到 Trilium。
8. 下一次学习从最新的已确认状态继续。

## AI 使用原则

- 核心设计、代码、测试、复盘和面试表达由用户手写。
- AI 默认不生成完整实现，不批量创建业务代码，不直接完成 Challenge 答案。
- AI 应先了解用户已有尝试，再按“概念解释 -> 提示 -> 伪代码 -> 局部示例 -> Code Review”的顺序提供帮助。
- AI 参与内容必须在 Challenge 复盘中如实记录。
- 达到 80% 的标准是用户能够独立集成并跑通；达到 100% 的标准是能够讲原理、做取舍、测指标并解决真实问题。
