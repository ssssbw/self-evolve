# AI 应用工程路线

## 定位

目标不是转纯算法或模型训练，而是成为能把大模型能力落到业务系统里的 AI 应用工程师。重点是工程闭环、业务建模、稳定交付和可解释的结果评估。

## 能力地图

| 能力层 | 必须掌握 | 验收方式 |
| ------ | -------- | -------- |
| 业务建模 | 把业务问题拆成输入、分析维度、输出和指标 | 能解释用户反馈评估系统为什么这样分类 |
| LLM 调用 | API 调用、Prompt、system/user message、结构化输出 | 能稳定输出 JSON，并处理异常格式 |
| 后端工程 | Python / FastAPI、数据库、任务处理、接口设计 | 能做一个分析任务接口和结果查询接口 |
| 数据处理 | 对话清洗、脱敏、切分、字段标准化 | 能把聊天记录转换为模型可用输入 |
| 结果评估 | 抽检、准确率、误判分类、人工反馈 | 能说明模型分析结果是否可信 |
| 成本稳定性 | 超时、重试、缓存、限流、日志、降级 | 能说明线上系统如何控制成本和失败 |
| 前端展示 | 报表、筛选、趋势、明细追溯 | 能把分析结果变成业务可用页面 |
| 移动端结合 | Flutter 接入 AI 能力和分析结果 | 能形成客户端 + AI 应用的组合优势 |

## 学习优先级

1. **先做当前公司项目需要的能力**
   - 对话记录结构化。
   - 分类体系和标签设计。
   - Prompt 与 JSON schema。
   - 报表指标设计。

2. **再补后端闭环**
   - Python 基础够用即可。
   - FastAPI 接口。
   - 数据库存储分析任务和结果。
   - 异步任务、日志和异常处理。

3. **最后补个人作品**
   - 用个人知识库做 AI 助手或 RAG 搜索。
   - 不使用公司数据。
   - 重点展示工程思路，不追求模型炫技。

## 暂不主攻

- 深度学习数学推导。
- 大规模模型训练。
- 论文复现。
- 纯算法岗刷题路线。

这些方向不是没有价值，而是和当前收入提升、跳槽准备、已有 Flutter 经验的衔接度较低。
