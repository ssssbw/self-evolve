# 作业 #011 — 观察者与策略模式练习

> 前置阅读：Refactoring.Guru「观察者模式」+「策略模式」  
> 建议语言：Dart  
> 目标：理解状态变化通知和算法替换的差别。

## 题目一（必做）：纯 Dart 实现 ChangeNotifier + ValueNotifier

不依赖 Flutter SDK，手写一个简易通知系统。

要求：

- 实现 `MyNotifier`，管理监听者列表。
- 支持添加监听者、移除监听者、通知监听者。
- 实现 `MyValueNotifier<T>`，值变化时通知。
- 写一个小测试：注册两个监听者，修改值，验证都收到通知。

思考：

- 谁是 Subject，谁是 Observer？
- 为什么监听者需要能移除？
- 如果通知过程中监听者修改监听者列表，可能有什么问题？

## 题目二（必做）：策略模式实现排序器

实现一个排序器。

要求：

- 定义 `SortStrategy`。
- 实现 `BubbleSortStrategy`、`QuickSortStrategy`、`MergeSortStrategy`。
- `Sorter` 接收策略并执行排序。
- 运行时可以切换策略。

思考：

- 策略模式和 if-else 判断排序类型相比有什么优势？
- 策略模式和命令模式有什么区别？
- Dart 中是否可以用函数代替策略对象？这样做的取舍是什么？

## 题目三（选做）：Provider / Riverpod 分析

要求：

- 画出简化数据流：Widget -> Provider -> Model -> notify -> Widget rebuild。
- 解释 `watch` 和 `read` 在观察者关系中的差异。
- 说明为什么错误使用 watch 可能导致不必要 rebuild。
