# 作业 #001 — 工厂方法与抽象工厂模式练习

> 前置阅读：Refactoring.Guru「工厂方法」+「抽象工厂」  
> 建议语言：Dart  
> 目标：区分“创建一个对象”的工厂方法和“创建一组相关对象”的抽象工厂。

## 题目一（必做）：工厂方法实现跨平台 Dialog

用工厂方法模式实现一个跨平台对话框。

要求：

- 定义 `DialogButton` 和 `Dialog` 抽象接口。
- 实现 `IOSDialog` / `IOSButton`。
- 实现 `MaterialDialog` / `MaterialButton`。
- 定义抽象创建者 `DialogCreator`，其中包含 `createDialog()` 工厂方法。
- 实现 `IOSDialogCreator` 和 `MaterialDialogCreator`。
- 客户端只依赖 `DialogCreator`，不直接 new 具体 Dialog。

思考：

- 为什么 `createDialog()` 是工厂方法？
- 如果只写一个 `createDialog(Platform platform)` + `switch`，和工厂方法有什么区别？
- 在 Dart / Flutter 里，这种模式什么时候值得用，什么时候会过度设计？

## 题目二（必做）：抽象工厂实现主题组件族

用抽象工厂实现一个主题切换系统。

要求：

- 定义 `ThemeFactory`，能创建 `AppButton`、`AppCard`、`AppBarStyle`。
- 实现 `LightThemeFactory` 和 `DarkThemeFactory`。
- 每个具体工厂创建同一主题下的一组配套组件。
- 写一个 `SettingsPage` 或伪 Widget，接收 `ThemeFactory` 并渲染 UI。
- 不允许在页面内部判断 `isDark` 后手动 new 不同组件。

思考：

- 为什么这是抽象工厂，而不是工厂方法？
- “一组相关对象”在这个题目里具体指什么？
- 如果新增 `HighContrastThemeFactory`，哪些代码应该改，哪些不应该改？

## 题目三（选做）：源码或项目分析

在 Flutter SDK、Dart SDK 或你自己的工作项目中找一个工厂方法 / 抽象工厂的影子。

要求：

- 写出具体类名、方法名或代码位置。
- 说明它更像工厂方法还是抽象工厂。
- 说明它解决了什么创建复杂性。
