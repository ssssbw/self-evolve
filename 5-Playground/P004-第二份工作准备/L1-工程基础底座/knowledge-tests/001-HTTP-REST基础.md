## 目标

验证自己是否真正理解 HTTP / REST 基础，并能把它用于后续 FastAPI、Next.js、AI 应用接口和 Self-Evolve AI 助手的 API 设计。

- 能解释一次 HTTP 请求从客户端到服务端再返回的过程。

- 能用 REST 思维设计资源接口。
- 能识别常见接口设计错误。
- 能把这些知识应用到 Self-Evolve 笔记元数据 API。

## 自测题

### A. 基础解释

1. HTTP 协议主要解决什么问题？它和 TCP 的关系是什么？
2. 一个 HTTP request 通常由哪几部分组成？每部分分别放什么？
3. 一个 HTTP response 通常由哪几部分组成？客户端如何判断请求是否成功？
4. URL、path、query string 分别适合表达什么信息？
5. header 和 body 的职责有什么区别？举 3 个常见 header。
6. `Content-Type` 和 `Accept` 的区别是什么？
7. HTTP 为什么常说是无状态协议？无状态会带来什么工程影响？
8. Cookie、Session、Token 解决的是什么问题？它们和 HTTP 无状态有什么关系？

### B. Method 与幂等性

9. `GET`、`POST`、`PUT`、`PATCH`、`DELETE` 各自适合什么场景？
10. 什么是幂等性？`GET`、`PUT`、`DELETE` 为什么通常被认为是幂等的？
11. `POST` 为什么通常不是幂等的？什么场景下需要额外设计幂等键？
12. 如果要“把一篇笔记标记为已索引”，你会用 `POST`、`PUT` 还是 `PATCH`？为什么？
13. 如果要“重新触发某篇笔记的 embedding 构建任务”，你会如何设计 method 和路径？

### C. Status Code

14. `200`、`201`、`204` 分别适合什么场景？
15. `400`、`401`、`403`、`404` 的区别是什么？
16. `409` 适合表达什么冲突？在笔记元数据 API 中举一个例子。
17. `422` 常见于什么场景？为什么很多后端框架会用它表达参数校验失败？
18. `500` 和 `503` 的区别是什么？AI 应用里什么时候可能返回 `503`？

### D. REST 设计

19. REST 中的 resource 是什么？为什么路径应该围绕名词而不是动词设计？
20. 比较下面两个接口，哪个更符合 REST？为什么？

```text
POST /createNote
POST /notes
```

21. 下面接口有什么问题？你会怎么改？

```text
GET /notes/delete/123
```

22. 下面两个查询场景分别应该如何设计？

- 查询第 2 页、每页 20 条笔记。
- 查询 P004 下包含 `HTTP` 标签的笔记。

23. REST API 中什么时候应该把信息放 path，什么时候放 query？
24. API 版本号可以放在哪里？例如 `/api/v1/notes` 和 header 版本控制各有什么取舍？

## 排错题

1. 前端请求后端接口时浏览器报 CORS 错误，这通常说明什么？应该从哪些地方排查？
2. 后端返回了 `200`，但前端解析 JSON 失败，可能有哪些原因？
3. 用户重复点击“创建笔记”，服务端创建了两条重复记录。这个问题和 HTTP / REST 的哪些知识点有关？
4. AI 分析接口经常超时。你会选择同步等待返回，还是提交异步任务后查询状态？为什么？
5. 一个删除接口偶尔失败，前端重试后成功。你如何判断这种重试是否安全？
