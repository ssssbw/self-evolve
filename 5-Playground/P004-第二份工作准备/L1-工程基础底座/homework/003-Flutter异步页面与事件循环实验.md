# 作业 003 — Flutter 异步页面与事件循环实验

> 所属项目：P004 第二份工作准备  
> 所属层级：L1 工程基础底座  
> 练习类型：Flutter coding 能力验收  
> 代码实现位置：你当前可运行的 Flutter 练习工程（建议单独建一个 `flutter-lab` 或放到现有 Flutter 工作工程的实验页里）  
> 状态：⬜ 未开始

## 目标

用一个小型 Flutter 实验页，验证你是否真的掌握了 L1 的异步基础，而不是只会背概念。

这份作业重点验证：

- 你能不能正确理解 `Future`、`await`、`mounted`、`event loop` 和 `isolate`。
- 你能不能把这些概念写进一个真实页面里。
- 你能不能区分“等待”和“并行计算”。
- 你能不能处理异步回来时页面已经销毁的情况。

## 任务

请实现一个 Flutter 页面，页面里至少包含 3 个实验区块。

### 任务 1：事件循环顺序实验

做一个按钮，点击后在控制台和页面上输出一组可观察的日志，包含：

- 同步输出
- `scheduleMicrotask(...)`
- `Future.microtask(...)`
- `Future(() {})`
- `Future.delayed(Duration.zero, ...)`

要求：

- 你要先写出自己预测的输出顺序。
- 再运行代码验证。
- 页面上要能看到最终顺序。

### 任务 2：异步回来后检查 mounted

做一个按钮，点击后触发一个模拟请求：

- 先显示 loading
- 等待一个 `Future.delayed(...)`
- 请求结束后更新 UI
- 如果页面在请求完成前已经退出，要先检查 `mounted` 再更新

要求：

- 你要能复现“页面退出后异步回来”的场景。
- 你要记录如果不检查 `mounted` 会发生什么。

### 任务 3：CPU 重任务用 isolate 处理

做一个耗时计算实验，例如：

- 大量循环求和
- 简单的 JSON 大量解析
- 其他明显会卡主线程的 CPU 任务

实现两个版本：

1. 直接在主 isolate 里跑。
2. 用 `compute` 或 `Isolate.run` 跑。

要求：

- 你要观察两者对 UI 响应的影响。
- 你要解释为什么普通网络请求不属于这个场景。

## 代码要求

至少写出以下内容：

- 一个用于记录日志的 helper。
- 一个展示事件循环输出顺序的实验逻辑。
- 一个异步请求后更新 UI 的页面逻辑。
- 一个 CPU 计算的 isolate 版本。
- 如果条件允许，补一个纯 Dart helper 的 unit test。

## 测试 / 验证要求

至少做 3 种验证：

1. 看控制台日志顺序。
2. 人工验证页面切换 / 退出后 mounted 行为。
3. 对比主 isolate 与 isolate 版本的 UI 卡顿差异。

如果你愿意补测试，优先写：

- 纯函数单元测试
- 事件顺序 helper 的测试
- 计算函数的测试
